Decision: publish CronScheduler prereleases and stable packages only to nuget.org, driven by GitVersion GitHubFlow/v1, with publish.yml triggered on push to master/dev (+ workflow_dispatch) instead of on pull_request closed.

Alternatives: keep feedz.io for previews (rejected by maintainer); Bet.Azure's trigger on pull_request types:closed (fires even for closed-unmerged PRs and builds the PR head, not the merged commit); publish only on tag push (cleaner, but maintainer wanted automatic previews).

Rationale: push-on-merge always reflects the merged commit and never fires for unmerged PRs; concurrency group prevents racing publishes. GitVersion develop branch must be mode ContinuousDelivery so each dev push gets a distinct 4.0.0-preview.N — ManualDeployment repeats preview.1 and --skip-duplicate silently drops later pushes. Feature branches use label '{BranchName}' with a (?<BranchName>.+) regex capture (GitVersion 6 syntax; 'useBranchName' is v5 and is emitted literally).

Consequences: every master/dev push publishes irreversibly (unlist only); tag/release created only from master when CommitsSinceVersionSource > 0.
