Pitfall: SchedulerFuncTests (from PR #57) slept a fixed Task.Delay(3-6 s) then asserted Times.Between(a,b) on second-level cron schedules — flaky (failed 2/2 runs on one machine, intermittently elsewhere), which would make pr.yml CI flaky.

Detected: the upgrade's test runs failed on Job_RunDelayed_And_Raise_UnobservedTaskException; the same failure reproduced on the untouched merged tree (git stash baseline), proving it pre-existing. Observed invocation count was 1, so not a scheduler double-fire — host startup simply exceeded the fixed window.

Avoid: never assert exact call counts after a wall-clock sleep for scheduler tests. Poll the same predicate the Verify uses (level + message) every ~100 ms with a >= 20-30 s timeout and Assert.Fail on timeout, then assert Times.AtLeast(min). Prove stability with 10 consecutive filtered runs (each must show total: N, failed: 0 — pin N so a zero-match filter cannot pass).
