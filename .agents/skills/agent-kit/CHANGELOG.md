# Changelog

All notable changes to the `agent-kit` skill. Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Versions follow [semantic versioning](https://semver.org) and are released as the git tag `agent-kit/vX.Y.Z`.

The kit version is `metadata.version` in [SKILL.md](SKILL.md); the emitter writes it into each install's `orchestration-kit.manifest.json` as `kitVersion`. Before re-adding with a new tag, read the target version's entry, especially its **Upgrade notes**.

## [2.2.0] - 2026-10-28

### Added

- **`flags.opt_in`** — optional boolean (`absent` ⇒ false; non-boolean ⇒ exit 3; persisted as manifest `options.opt_in` when present): drives IF flag `opt_in` and derived `OPT_IN_*` tokens. The three orchestrator skills (`feature`, `research`, `memory-capture`) get `disable-model-invocation: true` and end their descriptions with `Opt-in — runs only when the user types /<name>.` (`feature` replaces `Invoke for any non-trivial feature.`); the seven kit agent descriptions start with the scope prefix; ORCHESTRATION.md's skills note switches to opt-in wording for every research × loop variant; `auto-loop` path-Reads the feature skill; Cursor's `orchestration.mdc` switches to opt-in wording; Codex agent tables are prefixed on new installs with a partial-support warning; new Step 3 interview question.
- **`flags.kit_guard`** — optional boolean (`absent` ⇒ false; non-boolean ⇒ exit 3; persisted as manifest `options.kit_guard` when present): emits `_kit/kit-guard.sh` (`check` / `hook`) and `_kit/kit-guard.cmd`; Claude Code `PreToolUse` and Cursor `preToolUse` hooks blocking agent edits to kit-owned files (written only when `.claude/settings.json` / `.cursor/hooks.json` don't exist — otherwise emit warns with the merge snippet); read-only rule text and a kit-file gate in ORCHESTRATION.md, the feature skill's Phase 5, the writer agents, and the evaluator; `emit.sh --check` (no `--answers`; exits 0 / 2 / 4); Copilot and Codex partial-support warnings; new Step 3 interview question. With the guard on, Orchestration Progress lives in `_memory/work/goals/[goal]/progress.md` (ORCHESTRATION.md is kit-owned).
- **Evaluator floor and citations** — the `task-criteria` skill defines a kit-wide floor: F1 acceptance criteria met, F2 no regression in behavior the task touches, F3 the task's checks pass and changed behavior has a test that fails without the change, F4 tests never weakened, F5 no completion claim the evidence contradicts, F6 write fence respected and nothing dangling, F7 any bypass-class problem or a hang in normal use. In Phase 4 task evaluations, ladder re-evaluations and Phase 5 audits, every `blocker` or `major` finding cites exactly one of `AC<n>` (audits: `<TT>/AC<n>`), `SC<n>` or `F<n>`. A finding that cites nothing cannot block: it becomes a `[backlog]` note, and a verdict whose only findings are notes is `PASS (with notes)`. Required-fix lines carry the citation and one code-span location. The orchestrator's tag-check round trip (no cycle consumed) verifies every citation, first evaluations included. The evaluator agent, `evaluation-system.md` and the feature references agree.
- **Issue keys and `_kit/log-spawn.sh keys`** — each required fix serializes to one key, `<citation> <location> :: <defect>`, lower-cased with whitespace collapsed (kind and provenance tags never enter it, and `|` becomes `/`). `log-spawn.sh keys --goal <g> --spawn <NN> --task <TT|audit> --report <path>` appends one `KEYS` line per evaluation and one `REPEAT` line for each key also present in the same task's previous `KEYS` line, each entry carrying its kind and provenance tags. A second call for the same spawn number is refused with exit 3, and no other subcommand's output changes.
- **Early ladder entry under `ladder: auto`** — a `REPEAT` of a `[structural]` item ends the task's fix cycles early and proceeds exactly as on cycle-3 exhaustion (bypass check, rung 5 when its triggers fire, rung 4, rung 6). `[line-patch]` repeats, ladder re-evaluations and Phase 5 audits never trigger it; the ladder budget (3 additional implementation attempts) and every guard are unchanged, and the orchestrator logs `early ladder entry: <key>`. Under `ladder: escalate` (default) keys are log-only. The fix-cycles and continuation-ladder references, ORCHESTRATION.md, the evaluator and diagnostician agents, the Codex `AGENTS.md` pointer, the model map and the loop guides state it; loop goals always run `ladder: auto`.
- **`follow-ups.md` backlog and PR-body section** — uncited findings, demoted late findings and flaky or pre-existing quality failures become `B<n>` rows in `_memory/work/goals/<goal>/follow-ups.md` (orchestrator-written; status `open`, `fixed` or `wontfix`). `ship-pr` lists every `open` row under `## Backlog (not fixed here)` in the pull request body, and the Phase 5 final report lists them when Phase 7 is skipped.
- **Tree snapshots for re-evaluation** — at every evaluator spawn in Phases 4 and 5 the orchestrator records a working-tree snapshot through a temporary git index (`eval-tree [#NN] task <TT|audit>: <sha>` in the orchestration log), and each re-evaluation package carries `## Changed since last evaluation`: the paths changed since the previous snapshot within the write fence, or `none`.
- **Quality-failure classes with a dirty-file snapshot** — before Phase 4 the orchestrator saves `git status --porcelain --untracked-files=all` to `_memory/work/goals/<goal>/preexisting-dirty.txt` and never stages or edits those paths. A Quality Checks failure is narrowed, then classified: **flaky** (passes on one rerun; backlog row), **local-edits** (in or caused by a pre-dirty path; escalate), **pre-existing** (also fails on the merge base, run in a temporary detached worktree; interactive runs report it and offer a separate commit, loop and autonomous runs only add the backlog row) or **introduced** (goes to the implementer as a narrow fix). The `test-ladder` skill points at the classes.
- **Harness-matrix Cursor-hook addendum** — `reference/harness-matrix.md` gains a dated 2026-10-27 addendum of Cursor hook behavior, each fact marked staff-confirmed, documented, community-reported or unconfirmed, including the interaction with the `kit_guard` hooks. The stale 2026-10-08 cloud-hook row points to it.
- **`gate-hardening.sh` guard** — `tests/agent-kit/templates/gate-hardening.sh` locks the floor, the citation rule, the issue-key serialization, the late-finding scope, early ladder entry and their doc mirrors, with mutation proofs and a fresh-emit check.
- **Consumer trace** — the `goal.md` template gains `## Searches` (each search's literal command, hit count and verbatim hits, run through `terminal`) and `## Consumers` (one row per consumer of each shared surface a goal changes, classed `changes`, `unaffected` or `owner-excluded` with evidence; a goal that changes no shared surface writes `none — <reason>`), plus a `trace: planner|blind` key in the `phases:` block (default `planner`; an absent key means `planner`). Every install emits `_kit/trace-lint.sh` (no `jq`; exit 0 valid, 2 usage, 3 findings, 4 file missing or unreadable) and the `_kit\trace-lint.cmd` Windows launcher. In Phase 3 the goal evaluator names one to three searches to re-run whenever `## Searches` is non-empty, and its verdict stays provisional until the orchestrator resumes it with their output; under `trace: blind` a fresh read-only evaluator in the new consumer-trace mode writes its own trace from the problem statement and the surface list before attempt 1, and every consumer the planner's trace lacks is added to the trace as a pre-flight fix before attempt 1. The Phase 5 audit runs two checks, and a failure of either is a blocking finding citing `F6`: (a) a `changes` row whose evidence names a task must have its Consumer path among the changed paths, and (b) a shared surface the diff changes (tracked and untracked changes since `base-commit.txt`) must have a `## Consumers` row. A doc consumer that Phase 6 updates is a `changes` row with evidence `Phase 6` (only under `align_docs: true`).
- **Hook telemetry** — optional opt-in `flags.hook_telemetry` (boolean; `absent` ⇒ false; non-boolean ⇒ exit 3; persisted as manifest `options.hook_telemetry` when present): emits `_kit/hook-log.sh` and `_kit/hook-log.cmd`, with a `hook` command that logs stop events and a read-only `summary` command (counts by event, harness / agent type, status and model, plus the error and aborted runs). Claude Code `Stop` / `SubagentStop` / `StopFailure` and Cursor `stop` / `subagentStop` (each with `loop_limit: 1`) hooks are written only into a `.claude/settings.json` / `.cursor/hooks.json` that emit creates (combined with the kit-guard hook when both flags are on); an existing config is left untouched and emit warns with the snippet to merge, and a stale reference with the flag off gets a removal warning. Each stop event appends one metadata-only line (no task text, summaries, transcript paths or workspace paths) to the gitignored `_memory/work/hooks/events.jsonl`, rotated once to `events.1.jsonl` at about 5 MB. A payload is not appended again while its key (a hash of the raw payload) is still in events.jsonl or events.1.jsonl, the Claude Code hook does nothing when the caller is Cursor, and the tool fails open and never returns a follow-up message or block decision, so it cannot start an agent loop. Copilot and Codex get partial-support warnings. Three more pieces ship with it: a new Step 3 interview question (`Log subagent and session stops?`, default no), a hook-telemetry note in the emitted ORCHESTRATION.md (telemetry only, never a gate), and a `hooks/` line in the emitted `_memory/README.md` file tree. With the flag absent, emitted output is unchanged.
- **Hook telemetry logs `StopFailure` and an `error` field** — the Claude Code `StopFailure` event (a turn that ends on an API error) is logged as one line with `status` `"error"` and a new `error` field holding the documented error type (for example `rate_limit`), kept only when it is lowercase letters and underscores; `error` is `null` on every other line, and `error_details` and `last_assistant_message` are never logged. `summary` adds `error` to its errors-and-aborts lines (`-` when it is null or the line predates the field), and when the log holds no `claude` line it ends with a `hint:` line to check the Claude Code Stop hooks in the project settings. The `.claude/settings.json` that emit creates gains a guarded `StopFailure` hook after `Stop` and `SubagentStop`, the merge snippets include it, and an existing telemetry config that lacks it gets one warning with the entry to add. The harness matrix and the emitter docs record the hook.
- **Guarded Cursor hook command** — the Cursor `stop` / `subagentStop` hooks that emit creates, and the merge snippet, now run `test -f _kit/hook-log.sh && bash _kit/hook-log.sh hook cursor || echo '{}'`, the same guard the Claude Code command already had. On a fresh clone without `_kit/` the hook still prints the `{}` Cursor expects and Cursor logs no missing-script failure. Cursor's shell on Windows is unverified. Kit-guard-only and flag-off hook configs are byte-identical to before.

### Changed

- **Late-finding rule** — on re-evaluations a late `[new]` required fix blocks only when its location is in the package's `## Changed since last evaluation` list, when it cites `F1`, `F3`, `F4`, `F7` or an acceptance criterion, or when it is a reversal (which keeps its `criteria-defect` routing). Every other late finding becomes a `[backlog] [late]` note with its `— missed earlier:` clause; demoted notes still count toward the drift trigger (≥ 2 `[new]` items across cycles 2–3), so demotion never hides drift. Previously every late `[new]` item with a stated reason blocked.
- Default unchanged (auto-invocable orchestrator skills). With all three opt-in flags (`opt_in`, `kit_guard`, `hook_telemetry`) absent, emitted output is byte-identical to 2.1.0 apart from the changes listed in this release, including the evaluator-gate changes (the reworded templates and `_kit/log-spawn.sh`), the consumer-trace tool `_kit/trace-lint.sh` and its launcher (emitted on every install), and the emit warnings (the `warnings N` count and two new warning lines). Harness matrix and emitter docs record partial-support gaps on Codex and Copilot. `invocation-flags.sh` guard tolerates the IF-guarded flag line.
- **Gate-hardening follow-ups** — an unmet requirement that no acceptance or success criterion covers cites `F5`; `log-spawn.sh keys` keys an old-shape item without a citation as `uncited <location> :: <defect>` (lower-casing is ASCII-only); a reported model value starting with `unknown` logs `model_check: unverified`; and `ship-pr` prefixes backlog rows `<goal>/B<n>` in the PR body when it carries more than one goal. The pointers in ORCHESTRATION.md, the feature skill (its Phase 5 quality-check step now reads the log path, re-spawns `terminal` narrower, then classifies; the same words in a new order), the feature references, the evaluator (its Citations pointer names the audit form `<TT>/AC<n>` and the `### Issue key` section), `test-ladder` and `ship-pr` are corrected, and the guide gains a "Guarded installs (`flags.kit_guard`)" section.
- **Reference sweep retired** — pre-flight check 2 (missed callers) now verifies the `goal.md` consumer trace with `_kit/trace-lint.sh` instead of a free-form sweep, and `reference-sweep.md` is no longer written. Previously check 2 ran only for renamed or reshaped symbols and wrote a sweep file that nothing checked mechanically.
- **README rewritten as the kit's overview** — leads with what the kit does and why to use it (the "Why agent-kit" section cites Anthropic's [A harness for every task: dynamic workflows in Claude Code](https://claude.dev/blog/a-harness-for-every-task-dynamic-workflows-in-claude-code/) for the failure modes it addresses), adds a feature-flow diagram and an agent/tier table, and drops the security-scan section, the loop sandbox notes, and every hard-coded version number (the install pin now uses a `v<version>` placeholder). The README no longer carries a `Kit version` line; the test suite instead fails if a hard-coded `X.Y.Z` appears in it.
- **Failure modes stated explicitly** — the README's "Why agent-kit" section, the emitted ORCHESTRATION.md § Why This Architecture?, and the architecture guide now name the three single-session failure modes from Anthropic's [dynamic workflows article](https://claude.dev/blog/a-harness-for-every-task-dynamic-workflows-in-claude-code/) (agentic laziness, self-preferential bias, goal drift) and pair each with the kit mechanism that addresses it. ORCHESTRATION.md's problem table gains a goal-drift row and a "How this architecture answers it" column, and no longer claims fresh context "eliminates fatigue and bias completely". Documentation only; no behavior change.
- **Unattended-run rules stated explicitly** — the autonomous-loop guide gains § Unattended-run rules, mapping the six rules from Anthropic's [Building effective agent automations](https://claude.dev/blog/building-effective-agent-automations/) (resume from a bookmark, report a failed read as unreadable, re-check before acting, record only what is confirmed, keep the agent's rules out of its reach, read-only access plus spending caps) to the loop mechanisms that apply them, plus guidance on setting story budgets at three to five times a typical story's cost from the run ledger. The README's "It can run unattended" bullet cites the article, and the emitted ORCHESTRATION.md's loop guard table ends with a one-line pointer to it. Documentation only; no behavior change.
- **`warnings N` counts printed warnings** — emit's `warnings N` line now equals the number of warning lines printed on stderr. A retired kit-owned file that emit keeps because it was modified locally, and a file the previous manifest records that is now missing, each print a warning line (`warning: kept <path>: …`, `warning: <path> is recorded in the previous manifest but missing — nothing to prune`). Unanswered bootstrap ids stopped being counted: `--check-answers` lists them (exit 3), so an install with unanswered ids prints a lower `warnings N` than before. Informational `emit:` lines stay uncounted.
- **`trace-lint.sh` fixes** — `--help` is accepted only as the sole argument (next to anything else it is a usage error, exit 2); `~~~` fences are skipped like backtick fences and close only on the same character with at least as many marks; search ids compare as numbers, so `S01` and `S1` are one id and a repeat in either spelling is a finding; a leading `./` is stripped from Consumer cells before they are matched to hit paths; a `none — <reason>` trace must be the only non-blank line of `## Consumers` with `## Searches` absent; search items must start at column 0; and the script no longer uses here-strings.
- **Comma-grouped Footprint numbers** — `log-spawn.sh` reads a report line such as `files_read: 3 (~85,000 chars)` as 85000 characters, so `work_read_chars` and `work_est_tokens` are no longer n/a for large reads. A malformed group such as `85,00` still logs n/a.
- **`CDPATH`-safe paths** — `emit.sh`, `hook-log.sh` and `kit-guard.sh` run every directory-resolving `cd` with `CDPATH` unset, so an exported `CDPATH` can no longer add output to a resolved path or misdirect it. `hook-log.sh` also skips a payload whose top level is a JSON array.
- **Template wording and guard hardening** — wording and wrapping fixes in the ORCHESTRATION.md, evaluator, `task-criteria`, `goal-criteria`, fix-cycles, loop and `ship-pr` templates; ORCHESTRATION.md's file-location trees list `_memory/work/hooks/` under hook telemetry and its fresh-clone note describes the guarded Cursor command; the fix-cycles reference quotes the exact `## Provenance` heading with its scope. The `gate-hardening.sh`, `feature-feedback.sh` and `fix-cycle-provenance.sh` guards pin the new text and prove each pin with a mutation.
- **`run-all.sh` fails a suite whose checks all skipped** — `tests/agent-kit/run-all.sh` reads each suite's last summary line (`PASS:` / `SKIP:`, `summary: ok= … SKIP=`, or `SUMMARY: pass= … skip=`) and fails a suite that shows zero passes and at least one skip, even when it exits 0, because a suite that skipped every check proved nothing. A suite that skips everything on purpose (the Windows-only loop suite on another host) prints `ALL-SKIP-OK: <reason>` and is exempt; `AGENT_KIT_ALLOW_ALL_SKIP=1` turns the rule off, and `AGENT_KIT_SUITES` selects the suites to run. The new `run-all-rules.sh` suite proves the rule. Maintainer tooling only; no emitted output changes.

### Upgrade notes

- No action needed to keep current behavior: leave all three opt-in flags (`opt_in`, `kit_guard`, `hook_telemetry`) absent.
- **Opt-in:** copy the manifest's embedded `answers` into a file, set `"opt_in": true` under `flags`, run `bash <kit>/bin/emit.sh --answers <file> --upgrade`. An install whose kit files were hand-edited to exactly the emitted opt-in text upgrades with no blocked paths. If the hand edits differ in any byte (wrapping, extra notes), emit exits 4 listing those paths — move any non-kit customizations elsewhere (e.g. bootstrap answers), then re-run once with `--force`. **Codex:** an existing `.codex/config.toml` agent table is not rewritten; pointers already in `CLAUDE.md` / `AGENTS.md` / copilot-instructions are not rewritten.
- **Kit-file guard:** set `"kit_guard": true` the same way and re-run with `--answers … --upgrade`. If `.claude/settings.json` or `.cursor/hooks.json` already exists, merge the snippet the emit warning prints. Run `bash <kit>/bin/emit.sh --check` in CI to catch edited kit files (`check` needs no answers file). On failure, restore tracked files from git, delete a modified `_kit/` file, and re-run `emit.sh --upgrade` — never `--force` for kit-guard recovery. To remove the guard: set `"kit_guard": false` and re-run `--upgrade`; emit prunes `_kit/kit-guard.*` and warns for each hook config still referencing it — delete that entry. `_kit/` stays gitignored: on a fresh clone or CI checkout the guard script and hooks are inactive until emit runs, and `check` skips `_kit/*` entries there.
- **Hook telemetry:** to adopt on an existing install, set `"hook_telemetry": true` under `flags` in an answers file and run `bash <kit>/bin/emit.sh --answers <file> --upgrade`. Existing `.claude/settings.json` / `.cursor/hooks.json` are never edited; copy the snippet from the emit warning into them.
- **Evaluator gate:** re-emit with `--upgrade`; hand-edited kit files still block (exit 4) as before. In-flight goals keep their old verdict format until their next evaluation. The first goal after the upgrade writes `preexisting-dirty.txt` before Phase 4 and `follow-ups.md` rows as findings are demoted. Goals running `ladder: auto` (the autonomous loop always does) may enter the ladder before cycle 3 when a `[structural]` key repeats; `ladder: escalate` goals are unaffected.
- **Codex:** an existing install keeps its `AGENTS.md` pointer ("After three fix cycles, spawn `diagnostician` for rung 4 diagnosis"), because pointer files are never rewritten when their marker is present. New installs get the early-entry wording; edit the sentence by hand if you run `ladder: auto`.
- **Consumer trace:** re-emit with `--upgrade` to add `_kit/trace-lint.sh` and `_kit\trace-lint.cmd`. Goals planned before the upgrade (no `## Consumers` section) keep being checked against their `reference-sweep.md` until their next material amendment, and skip the Phase 5 consumer check (the audit checks that artifact instead); goals planned after the upgrade write the trace.

## [2.1.0] - 2026-10-27

- **`_kit/memory.sh prune`** — deterministic `--plan` / `--apply` deletion of `_memory/work/goals/<goal>/` and `_memory/work/research/<topic>/` folders once every record id on the goal's latest `ARCHIVED:` line (or, without one, every `goal <g> (goal.md)` record) or on line 2 of the research `ingested` marker is committed in `HEAD` and, when the repo has a remote default branch (`origin/HEAD`, else `origin/main`, else `origin/master`), merged there; keeps everything else with a `keep:<reason>` (including `keep:unmerged:<id>` and `keep:tracked`), never follows symlinks, keeps all with `keep:no-git` outside git.
- **Feature Phase 2 prune step** — the orchestrator runs `prune --apply` once before recall and logs the summary in the new goal's orchestration log.

### Changed

- **Memory and orchestration docs** — memory protocol (`## Prune`), `_memory/README.md` (`prune` section, usage, exit codes), ORCHESTRATION.md (Phase 2 note, memory table row, `_kit` tool lists, command example), and the harness matrix document the command.

### Upgrade notes

- Re-emit with `--upgrade`; the next feature Phase 2 deletes finished `_memory/work/` folders whose records are committed and merged — fetch first so `origin/…` is current, or folders simply stay until the next run; run `_kit/memory.sh prune --plan` first to see what would go; pruned goals stop giving `memory-capture` goal-folder hints.

## [2.0.0] - 2026-10-26

### Removed

- **`loop.ps1`, `breaker.ps1`, and `memory.ps1`** — the emitter no longer writes PowerShell loop or memory twins; re-emit with `--upgrade` prunes unmodified copies (see Upgrade notes).
- **Emitter `pwsh` parse-check verify step** — kit scripts are Bash-only; verify no longer runs PowerShell syntax checks on removed twins.

### Added

- **`_loop\loop.cmd` Windows launcher** — loop-enabled installs emit a Git-Bash-backed launcher beside `_loop/loop.sh` for cmd and PowerShell on Windows (Git for Windows required).
- **Windows CI leg and Windows-only loop test** — a non-blocking `windows-latest` CI job runs the loop harness and a Windows-only loop test under Git Bash (through `_loop/loop.sh`) that reports both known limitations: `.cmd` shim resolution and native child processes after a slot timeout.

### Changed

- **Bash-only kit scripts** — every former bash-only knob (loop dossier, budgets, tamper check, ledger, lint, usage formats, breaker probe, memory backfill) is simply a kit knob on `_loop/loop.sh` and `_kit/memory.sh`.
- **Sandbox wording** — emitted templates and `SKILL.md` state that a worktree separates the git tree but is not isolation when permission prompts are skipped or the CLI sandbox is disabled.
- **New installs and `*.ps1` in `.gitattributes`** — fresh emits no longer append `*.ps1 text eol=lf`; existing lines in a project's `.gitattributes` are left alone on upgrade.
- **README security section** — Socket severity wording, loop permission-settings phrasing, and deterministic-emit caveats (`installedAt` / `EMIT_DATE`) aligned with manifest behavior.

### Upgrade notes

- Re-emit with `--upgrade` deletes unmodified `_loop/loop.ps1`, `_loop/breaker.ps1`, and `_kit/memory.ps1`; modified copies are kept and reported as warnings — delete them by hand when you are ready.
- Replace `pwsh _loop/loop.ps1 …` with `_loop\loop.cmd …` from cmd or PowerShell (Git for Windows required) or `_loop/loop.sh …` in Git Bash.
- Existing `*.ps1 text eol=lf` lines in `.gitattributes` are not removed by upgrade; new installs no longer add that line.
- Two Windows loop behaviors are known limitations, confirmed on the Windows CI leg — see [reference/windows-launcher.md](reference/windows-launcher.md) § Loop on Windows: known limitations (orphaned native processes after kill/timeout; `.cmd` shim resolution and cmd.exe argument truncation when `LOOP_CLI` points at a `.cmd` file).

## [1.1.3] - 2026-10-23

### Added

- **Loop run ledger and summary** — the bash driver appends one JSON line per reaped or killed slot to `_memory/loop/ledger.jsonl` by default (`LOOP_LEDGER=off` disables); after at least one reap or kill it prints an outcome and token/cost summary on stderr (not in `--lint` mode).
- **Loop iteration timeout and budgets** — bash-only knobs `LOOP_ITER_TIMEOUT`, `LOOP_RUN_BUDGET_TOKENS`, `LOOP_STORY_BUDGET_TOKENS`, `LOOP_RUN_BUDGET_USD`, `LOOP_STORY_BUDGET_USD`, and `LOOP_ITER_BUDGET_USD` (Claude Code per-dispatch cap); run budgets stop claiming new stories (exit 1 when eligible work remains); story budgets block the story and append `_memory/loop/ESCALATIONS.md`; missing usage/cost fails open.
- **Loop tamper check** — `LOOP_TAMPER_CHECK` (`warn` default, `fail` worktree-only, `off`) with optional `LOOP_TEST_PATTERNS`; `fail` quarantines with reason `tamper`.
- **Loop backlog lint** — `_loop/loop.sh --lint [backlog-path]` reports errors and warnings with no side effects (exit 0/1/5).
- **Fix-cycle provenance tags** — re-evaluation and re-audit required fixes are tagged `[carried]` / `[regression]` / `[new]`; late `[new]` items need a reason and are logged; task reversals route as `criteria-defect` and re-audit reversals escalate to the user; rung 5 arbitration also runs when ≥ 2 `[new]` items appear across cycles 2–3; re-evaluation packages carry every earlier required-fixes list.
- **Loop attempt dossier** — bash-only `LOOP_DOSSIER` (default on) stores the two newest failed-reap entries (~2048 bytes each) under `_memory/loop/attempts/<story-id>.md`, injects a fenced DATA block on the next dispatch, and deletes the file when a reap sets `passes: true`; slots write `<outbox>/attempt.md` (1500-byte cap).
- **Loop `claude-stream` usage format** — opt-in `LOOP_USAGE_FORMAT=claude-stream` splices `--output-format stream-json --verbose`, detects rate limits from typed `system`/`api_retry` events with `error` `rate_limit` or `overloaded`, falls back to stderr text plus the final result envelope only, and is never chosen by `auto`; `LOOP_ITER_BUDGET_USD` applies as for `claude`.
- **README security section** — explains the skills.sh scan flags (command execution, indirect prompt injection, transcript access, external downloads, dynamic execution), why each capability exists, and what limits it (marking prompt-only rules as *Instruction*), plus the loop sandbox requirement; the autonomous-loop guide now states that a worktree alone is not isolation for skipping permission prompts.
- **Loop upward breaker recovery** — bash-only probe of the preferred model after a rate-limit fallback: first delay 1800 s, doubling with an 1800 s floor and 14400 s cap; success stays on the preferred model, failure restores the pre-probe model (`breaker.ps1` has no upward path).

### Changed

### Added

- **Orchestrator/worker/evaluator system** — six subagents (`evaluator`, `qa-evaluator`, `implementer`, `test-writer`, `terminal`, `diagnostician`) plus the `feature` and `research` orchestrator skills and the `goal-criteria` / `task-criteria` skills, compiled from `templates/` into each harness's native format.
- **Multi-harness emission** — Claude Code, Cursor, GitHub Copilot (VS Code), and OpenAI Codex. Cursor gets a fully self-contained `.cursor/` tree (agents, skills, architecture doc, model map) with no `.claude/` cross-reads; Copilot gets both `.github/agents/feature.agent.md` and `.github/skills/feature/SKILL.md`.

Flags: `--answers`, `--upgrade`, `--dry-run`, `--force`, `--check-answers`, `--root`, `--kit`. Exit codes: 0 ok · 2 usage/unreadable · 3 answers invalid · 4 upgrade blocked (user-modified; `--force` overrides) · 5 verify failed · 6 template syntax. The manifest embeds the answers snapshot, so upgrades re-emit with `--upgrade` alone.
- **Template grammar** — `<!-- BOOTSTRAP[id]: … -->` slots, `<!-- IF flag -->` … `<!-- ENDIF flag -->` (and `!flag`) conditional spans, and `{{TOKEN}}` placeholders, resolved in that order. Template skills are named `SKILL.template.md` so harnesses never discover them as live skills.

- **Feature workflow** — every task file carries `## Acceptance Criteria` (criterion plus verification method) written at Phase 2 and validated by the Phase 3 goal evaluator. Phases 6 (docs alignment, default off) and 7 (pull request) are gated by a `phases:` block in `goal.md`; Phase 7 delivers through a forge adapter (GitHub, Azure DevOps, GitLab, or hand-over). The orchestrator reads ORCHESTRATION.md per phase rather than whole.
- **Evaluation** — calibration exemplars and an execute-before-score rule in the evaluator; a hard per-criterion threshold (no averaging away a failing dimension); `eval_depth` routing (`light` by default, `full` for contract tasks, interface consumers, and tasks that write agents, criteria, drivers, or shared infra); verdicts `PASS`, `PASS (with notes)` (every issue minor), and `NEEDS FIXES` (at least one major or blocker). Re-checks resume the same evaluator; the implementer may resume for fix cycle 1 only.
- **Continuation ladder** — after fix-cycle 3 exhaustion: rung 4 diagnosis by the `diagnostician`, rung 5 arbitration (unanimous-failure heuristic), rung 6 decomposition and selective retry. Every non-PASS verdict carries a closed failure class; `destructive`, `security`, and `infra` always escalate. Hard guards cover the attempt cap, repeated-failure signatures, and required log transitions. `ladder: escalate|auto` in `goal.md` (default `escalate`; the loop sets `auto`). The ladder lives in the feature skill's `reference/continuation-ladder.md`.
- **Model tiers** — frontier, light, and an optional fast tier (`models.<harness>.fast`; `terminal` pins to it, falling back to light when omitted). Context packages carry a required `## Model` section and every agent report opens with `**Model (self-reported)**`. Per-role effort: diagnostician `xhigh`, terminal `low`.
